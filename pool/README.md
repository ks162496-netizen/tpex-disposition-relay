# 當沖股票池（pool/）

這個資料夾放的是「下一個交易日可以考慮當沖的股票清單」，由 GitHub Actions
自動產生（程式：`scripts/build_pool.py`，排程：`.github/workflows/build-pool.yml`）。

## 檔案

- `latest.json`：最新一次產生的股票池（給程式讀這個就好）。
- `YYYY-MM-DD.json`：以「目標交易日」命名的股票池，例如 `2026-11-06.json`
  是給 11/6 開盤用的。只保留最近 30 份，更早的可在 git 歷史找到。
- `../data/cache/*.json`：每個資料來源最後一次成功抓到的內容（備援用）。
- `../data/last_run.log`：最近一次執行的紀錄，失敗時先看這裡。

## 日期怎麼算

- `target`（目標日）：下一個要交易的日子。下午 2 點前執行，若今天是交易日，
  目標就是今天；否則是下一個交易日（跳過週末與證交所公告的休市日）。
- `data_date`（資料日）：目標日的前一個交易日，也就是用哪一天的收盤價與成交量。

## 入選規則（全部符合才入選）

1. 普通股：上市為 4 位數代號（1–9 開頭、不含 91 開頭的存託憑證）；
   上櫃以證交所 ISIN 清單中「股票、CFI=ESVUFR、上櫃」為準。
2. 公司基本資料有產業別。
3. 有 `data_date` 當天的收盤資料。
4. 收盤價介於 20 元到 600 元（含）。
5. 成交量至少 500 張（50 萬股）。
6. 上市：不在變更交易（全額交割）名單；上櫃：沒有變更交易、分盤交易、
   管理股票、停止交易等註記。
7. 目標日不在處置期間內。
8. 目標日沒有停牌。
9. 在目標日的「可當沖標的」名單上。名單中標註「暫停先賣後買」的股票仍會入選，
   但 `sell_first_suspended` 會是 `true`（只能先買後賣）。

沒入選的股票會列在 `excluded`，並寫出第一個不符合的原因，例如
`low_volume`（量不足）、`price_out_of_range`（股價不在範圍）、
`disposition`（處置中）、`not_daytrade_listed`（不在當沖名單）。

## 資料來源出問題時

- 每個來源最多試 3 次；仍失敗就用上次成功的備份，並在 `sources` 中標成
  `stale_cache`（附上資料日期），不會因為單一來源失敗而整份不產生。
- 目標日的當沖名單還沒公布時，先用最近一次公布的名單，並在
  `daytrade_fallback` 標成 `true`、`daytrade_list_date` 寫出實際名單日期。
- 某市場的公司資料或收盤資料完全拿不到時，該市場會被略過，寫在
  `skipped_markets` 與 `warnings`。
- 若整份股票池是空的，就不覆蓋既有檔案（保留上一份），並讓這次執行顯示失敗。

## 自動執行時間（台灣時間）

| 21:40 | 一～五 | 補抓較晚公布的名單 |
| 23:20 | 一～五 | 補抓較晚公布的名單 |

| 07:40 | 一～五 | 開盤前最後一次更新 |

也可以在 GitHub 的 **Actions → Build day-trade stock pool → Run workflow** 手動執行。

## 檔案欄位（SIMPLE_POOL_V1）

- `members`：入選股票，每筆有 `market`（TWSE 上市／TPEX 上櫃）、`symbol`、`name`、
  `industry`（官方產業代碼）、`close`、`volume_lots`（張）、`sell_first_suspended`。
- `counts`：入選總數、各市場數量、各排除原因的數量。
- `sources`：每個來源的狀態（`fresh` 新抓／`stale_cache` 用備份／`failed` 失敗）、
  資料日期、筆數、抓取時間、錯誤訊息。
- `warnings`：需要注意的情況（例如名單用了前一天的版本）。
